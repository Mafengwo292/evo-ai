## Why "Self-Evolving" and not "Self-Improving"?

Most "self-improving" systems tweak prompts, hyperparameters, or fine-tune on user feedback. **We evolve the actual weight matrix** using (1+λ)-ES evolutionary strategy with 5 anti-mode-collapse mechanisms:

1. **Shannon entropy reward**: prefer outputs with rich vocabulary
2. **Diversity reward**: punish repetition within output
3. **Format reward**: prefer well-structured text
4. **Perplexity reward**: prefer likely-but-not-too-likely tokens
5. **Novelty reward**: prefer outputs not seen in training data

Each generation: parent weight → mutate 8 variants → pick best → repeat.

## What we tried and learned

1. **Memory matters**: 1.8GB server can't load 813K + torch (3.5GB needed). Solved with `light_api.py` (~200MB).
2. **Tunnel rotation**: SSH tunnels die when parent process exits. Solved with watchdog that auto-restarts every 5 min.
3. **Cron jobs die**: Server rebooted at some point, crond was disabled. Now enabled + monitored.
4. **GitHub PATs are sticky**: Classic PAT with `repo` scope is enough to create repos, fork, and PR.
5. **Random Wikipedia ≠ useful training data**: Switching from random to AI-curated articles doubled evolution progress.
